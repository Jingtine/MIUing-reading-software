# 文字阅读控件与代码整理 · 0.6.0

本轮继续以 EPUB/TXT 为重点。正文页改为右上关闭、安静的章节状态、底部本章页码和右下阅读菜单；目录、主题、搜索、书签、高亮笔记与章节进度集中在菜单中。依据及与原版的区别见 [参考记录](reference/reader-chrome-reference.md)。

## 结构与行为

- `TextReaderChrome` 仅绘制正文上的覆盖控件，菜单在 `ReadingMenu`；二者通过参数和回调工作，不直接读写书库。
- 目录、书签、笔记、搜索和编辑界面移入 `ReaderPanels`；弹层使用 `ReaderPanel` 枚举路由，`ReaderScreen` 负责现有状态与阅读操作。删除已经失去调用路径的旧文字工具栏代码，保留 PDF 的既有行为。
- 正文始终保留相同的上下空间，尺寸和控件共用同一组边距。显示/隐藏控件、打开菜单和选择文字均不改变正文视口；可保存和恢复打开中的菜单。
- 菜单前往目录、搜索或主题时先关闭自身。书签操作复用现有持久化路径；主题草稿、高亮的精确文字范围和离线/CSP 边界继续保留。
- 页码由实际 WebView 章节分页报告，过滤已经销毁的桥接回调。重新排版后更新；滚动模式使用百分比。没有新增依赖或应用权限。
- 对版本号 69 及更早的旧 Chromium WebView 使用软件绘制，处理已在 Android 8 / Chrome 69 上复现的弹层合成黑块；新版本继续硬件加速。没有更换阅读引擎或增加通用兼容框架，旧版软件绘制的帧时间尚未测量。

## 验证记录

日期：2026-11-19。两项新增阅读控件测试先在 0.5.0 因缺少“阅读菜单”失败。新控件集成后，与主题两项、定位/高亮一项一起专项 5/5 通过。测试真实导入 EPUB，执行实际菜单、书签、章节/目录/搜索、主题与 Activity 重建，并比较 WebView 尺寸和正文锚点。

首轮完整回归发现超过 600ms 的横向慢滑被旧逻辑按长按忽略。新增慢滑与原地长按测试，先复现失败，再区分位移方向与持续时间；文字选择继续阻止翻页。

一次独立只读审查指出字体延迟载入的页数刷新、状态文字对比度以及进度/书签测试覆盖问题，并发现无障碍书签名称和测试等待中的两处小问题。本轮均已处理：

- 使用设备自带 Roboto 字体，通过真实 WebView 请求延迟载入；先复现实际 201 页但仍报告 336 页，再验证字体就绪后刷新正确，且不额外写入阅读进度。专项 1/1 通过。按配置身份过滤旧字体回调，单纯翻页不会取消当前字体的页数刷新。
- 原始和安静主题的小号状态文字对比度原为约 3.59:1、2.74:1，改用主题正文色；六主题及全局深色的状态色计算对比度最低为 5.24:1。书签无障碍名称明确区分添加/移除。
- 增加真实菜单滑块跳到章中、原生持久化锚点、保存书签并从书签返回原段落的验证；原生页码检查章首、章末、增大字号后的总页数，避免只有前缀断言。另验证小高度横屏菜单滚动后可进入笔记，关闭按钮保持可达。这些测试与慢滑修复专项均通过。

## 仍需继续

这是一次文字阅读控件对齐和有边界的代码整理，并非完整 Apple Books 复刻。展开菜单的精确视觉、全书分页、位置返回历史、分享与方向锁定、跟手卷页、书库逐页校准仍需后续工作。实体设备尚未验证。没有引入通用状态框架，也没有重写 PDF 服务和书库持久化。
