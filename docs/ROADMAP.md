## 一、产品方向

做一款可长期自用的 Android 本地阅读器，以可重排文字阅读为核心，覆盖手机和平板，保持接近 Apple Books 的视觉层级、布局、主题和阅读操作。

- 平台：编译/目标 API 36，兼容下限 API 26；在实际窗口尺寸上验证手机、平板、横竖屏和分屏。
- 内容：现有无 DRM 的 EPUB、TXT、MOBI、AZW、AZW3、FB2，保留已实现的 PDF 能力；继续优先解决文字书体验。
- 字体：界面跟随 Android 系统字体，保留用户指定的内置正文字体及个人版字体隔离。
- 功能参考：成熟阅读平台提供本地阅读功能与操作流程的参考；Apple Books 提供视觉和交互基准；具体技术优先从 GitHub 已有实现筛选复用。
- 当前范围排除账户、推荐和云同步；在线书城、广告、付费体系不列入此份本地阅读器计划。

## 二、当前已经具备的基础

现有七种格式导入、私有阅读副本、书库和藏书、目录、分页/滚动、整本进度、主题/字体、书签、精确高亮、笔记、脚注、全书搜索、原文返回、系统打开/分享接入和本地备份恢复已经落地。0.7.5 补充笔记分组、筛选和 TXT/Markdown 导出。

当前范围和边界以 [对照清单](reference/parity.md) 为准，最近的交付证据见 [0.7.5 记录](releases/notes-export-0.7.5.md)。后续应验证和完善这些基础，避免重复重建已有功能。

主要缺口是大书搜索等待、更多真实书籍样式、原版页面精细对照、异常场景覆盖和实体设备验证。当前仍是开发签名安装包。

## 四、0.7.6 大书搜索与性能工作记录

### 现状与改动边界

0.7.4 已按命中列出上下文并支持跨章节导航。0.7.6 增加边扫描边打开结果、最近一次完整结果缓存，以及排版变化后按正文锚点恢复选中项。首次搜索仍逐章扫描，每章有超时保护。

首先检查以下现有代码及测试，而非建立另一套阅读引擎：

- [BookSearch.kt](../app/src/main/java/com/miuing/reader/BookSearch.kt)：逐章扫描、进度与数量限制。
- [ReaderScreen.kt](../app/src/main/java/com/miuing/reader/ReaderScreen.kt)：搜索生命周期、结果选择与原文返回。
- [ReadingPreview.kt](../app/src/main/java/com/miuing/reader/ReadingPreview.kt)：共享预览渲染器和回调管理。
- [reader-text.js](../app/src/main/assets/reader-text.js)：正文匹配、命中序号与上下文。
- [搜索实现与测试记录](releases/book-search-0.7.4.md)：已有约束、测试和性能边界。

### 执行步骤

1. **先查 GitHub。** 从已核验的 Foliate、Readium、KOReader 等方案中检查搜索调度、缓存与定位做法，记录实际代码路径、固定版本、许可和取舍。仅使用符合项目条件的代码；功能参考与直接源码复用分别注明。
2. **建立可比较的基线。** 固定短书、多章节长篇和图文 EPUB，记录样本摘要、设备、WebView 版本、首批/完整/重复搜索耗时及内存。先取得测量，再确定具体性能门槛，不编造提升比例。
3. **补一份短实施设计。** 根据测量选择章节缓存、查询结果缓存或预览调度优化；写清容量上限、取消、内容变化和布局变化时的失效规则。保留中文子串、隐藏内容、Unicode 和原文定位的现有语义。
4. **先打通增量结果。** 已完成章节的结果可打开；用户点击、换词或关闭时，旧任务不得覆盖新状态，跨章导航和返回来源继续正确。
5. **按证据加入缓存。** 缓存命中必须与当前书籍内容和匹配规则对应；影响可见文本的条件变化时失效。控制缓存大小，不把整书重复常驻内存。
6. **执行针对性验证。** 新增真实行为的回归，运行核心/JVM 检查及相关设备测试，覆盖取消、快速换词、点击未完成搜索结果、旋转、换字体和跨章。渲染资源继续遵守现有最多两个 WebView 的约束。
7. **比较并交付。** 用同一批样本报告前后数据、仍有的限制和审查结果；完成后再提升版本并打包常规/个人 APK，保存摘要和验证记录，提交推送。

### 本任务完成条件

- 搜索期间已找到的结果能够打开，且匹配位置与现有正确结果一致。
- 重复搜索或缓存命中有可复现的改善证据；若某种缓存没有收益，记录原因并采用测量支持的方案。
- 关闭、换词、切书、旋转和调整排版后，没有迟到回调串结果或遗留渲染器。
- 现有书籍、进度、批注和备份格式保持兼容。

## 五、后续工作的工程规则

- 一次只推进一个可独立验收的任务。用已有模块和稳定库解决问题，新增依赖前核对用途、许可、体积和平台适配。
- GitHub 调研应定位到真实源码与版本，不能只根据 README 或项目名称决定接入。大型工具包是否采用，要看与现有解析、渲染和数据层的匹配程度。
- 共享解析、定位和缓存能力保持单一职责；新工作不持续堆入 `ReaderScreen.kt`。已有大文件仅在当前改动确有需要时拆分。
- 测试以真实失败模式为目标，先覆盖相关流程；仅当变更范围、失败或未解决风险需要时扩大回归。常规任务不重复运行没有变化的整套设备测试。
- 维护简短阶段记录和验收证据；不重复复制整个项目历史。按 [工作区整理规则](maintenance/workspace-2026-11-25.md) 放置临时输出、截图和交付包。

### 0.7.8 后的 TXT 换行修复（2026-11-25，尚未发布新安装包）

- 先核对 [calibre TXT 处理](https://github.com/kovidgoyal/calibre/blob/master/src/calibre/ebooks/txt/processor.py) 的 `clean_txt`，其先统一换行再处理段落。读取的文件 blob 为 `ba0d093b2c530b5a1dcdb230481894dff691a669`。仅参考处理顺序，未复制 GPLv3 代码或加入依赖。
- 合成回归复现：UTF-8、带 BOM 的 UTF-16、GB18030 的纯 CR 换行文件中，两章被解析成一章；混合 CR/CRLF/LF 会丢失空行。旧实现仅归一 CRLF，补充独立 CR 到 LF 的转换即可修复。
- 新增 10 组测试，检查章节、标题、空行、缩进、HTML 转义、正文和原始文件字节未改变。修改前 31 项通过、4 项失败；修改后核心 35 项全部通过，应用 JVM 测试与 Android debug 编译通过。此次未执行设备测试，未重新发布 `dist` 安装包。
- 当时发现的兼容风险：原先已经导入的纯 CR 或混合 CR 文件在重新打开时会重新分章，旧进度与批注位置可能受影响。下述分章版本兼容修复已阻止已发布版本旧书的自动重分章。

### TXT 旧书定位兼容（2026-11-25，尚未发布新安装包）

- 先查 [Readium locator 模型](https://github.com/readium/architecture/blob/master/models/locators/README.md)，读取文件 blob `ac3611250cd31e1aa34d2c8544ed3c640911b76a`。位置属于具体出版资源；本项目的章节编号和章内偏移也依赖稳定的章节内容。仅参考模型，未引入依赖。
- 方案采用保存分章版本，避免自动重分章改变旧位置。`Book.txtLayoutVersion` 缺省为旧版 1，新导入 TXT 设为 2；重新打开时传给同一个解析器。旧版仅归一 CRLF，新版另外归一独立 CR。现有书籍重复导入保留旧记录，备份和恢复通过共用 `BookJson` 保留版本，未知 TXT 版本明确拒绝。
- 先用 Android 16 回归复现旧记录由一章变为两章的失败，修复后 TXT 兼容 3 项和备份 15 项全部通过。检查覆盖旧章节 HTML 字节一致、进度/书签/笔记记录、重新加载书库、重复导入、删除原书库后的备份恢复，以及新书仍按修正规则分章。核心 37 项、应用 JVM 10 项和 Android 编译通过。
- 此次是保留旧布局的兼容方案，不包含旧批注到新章节的自动迁移；没有执行阅读界面选中高亮位置、实体设备或应用降级验证。前一提交的无版本 TXT 修复未发布安装包，不将其临时测试书库纳入已发布版本升级保证。正式升级验收仍需在发布阶段覆盖。
