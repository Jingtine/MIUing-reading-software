# 0.7.2：文字阅读真实样书兼容性

本轮先检查 GitHub 的 Foliate-js、Readium Kotlin Toolkit 以及 W3C/IDPF 公开样书。选择复用已有 Foliate 模块的标准字体资源算法，接入现有 Java EPUB 解包流程，保留统一文字阅读器与记录格式。没有增加运行时依赖、网络权限或另一套导航界面。

## 已改善的行为

部分 EPUB 的内嵌字体使用标准字体混淆。旧实现会原样解压，导致真实 WebView 拒绝加载字体而回退。现在支持 IDPF（前1040字节）和 Adobe（前1024字节）两种标准方案，字体的其余字节与原始 EPUB 保持不变。

IDPF 按主标识符及 XML 空白规则计算 SHA-1；Adobe 使用有效 UUID。处理仅限清单中声明的本地字体，支持有字体 MIME 但没有常见后缀的文件；通用二进制 MIME 需字体后缀。重复声明只变换一次，冲突、异常路径、缺少标识符、未声明目标及其他加密方式明确报错。只在完整校验声明后修改解压副本，变换缓冲区最大1040字节。

沿用字体选择、主题、文本锚点、书签和批注。旧版仅保存阅读比例的记录仍使用比例回退，字体重新排版后无法保证逐字相同位置；已有文本锚点的记录优先恢复原文。

## GitHub 复用来源

- [Foliate-js epub.js](https://github.com/johnfactotum/foliate-js/blob/78914aef4466eb960965702401634c2cb348e9b1/epub.js#L554-L597)：固定提交 `78914aef4466eb960965702401634c2cb348e9b1`，文件 blob `e8bd70333accb9f9f6fb7389cb434b6805156da0`，MIT。算法按现有 Java IO 适配，来源、修改说明及作者见 `third_party/foliate-js/EPUB-FONT-ADAPTATION.md`；已有 Foliate MIT 许可继续随 APK 分发。
- [Readium Kotlin Toolkit](https://github.com/readium/kotlin-toolkit)：核查其 EPUB 导航、定位和阅读能力，本轮未引入；整套内核迁移需要另行处理现有定位、批注与界面接入。
- [W3C/IDPF EPUB 3 Samples](https://github.com/IDPF/epub3-samples/tree/7651e2002b631e6577fadf7e9e0692fa6efb8746/30)：固定提交 `7651e2002b631e6577fadf7e9e0692fa6efb8746`。通过原始 Git blob 构建测试 EPUB，逐一核对 blob SHA，避免 Windows 换行转换改变样书。样书与字体仅保留于本地忽略目录，不进入 Git 或 APK。

公开样书默认 CC-BY-SA 3.0，例外以样书元数据为准，内嵌字体保留自身许可；参见上游 README 及样书元数据。项目分发的是构建与验证代码。

## 可复现验证

构建与进程恢复工具见 [测试说明](../tools/epub-compatibility/README.md)。新增9项核心字体测试，覆盖字节向量、主标识符、Unicode/XML空白、UUID大小写、边界及后缀、重复打开、路径和冲突。最初8项全部失败，修复后通过；无后缀 MIME 用例单独先失败再通过。

Android 字体控制组中，普通字体加载成功，两个混淆字体真实加载失败（3项中2失败，14.312秒）；适配后3项通过（17.720秒）。测试等待 `document.fonts.load` 返回加载完成的字体，而非只检查 CSS 字体名称。

独立样书包括 `wasteland-otf`、`wasteland-otf-obf`、`wasteland-woff`、`wasteland-woff-obf`、`moby-dick`、`internallinks`、`childrens-literature`、`epub30-spec`，合计8本、5,037,723字节。6个解码字体分别与上游未混淆原件的完整 SHA-256 匹配；OTF/WOFF 三种字重/样式在实际阅读 WebView 加载成功。8本均验证导入、原文件校验和目录解析，实际阅读页字体检查聚焦两本混淆字体样书。真实样书的 noteref/rearnote 脚注也已验证弹层内容、原字体继承和关闭后的原文锚点。
