# 文字阅读引擎优化 · 0.6.2

本轮优化 EPUB/TXT 的定位和高亮计算，保留 Android16/API36 主适配、原有页面组织、书签/笔记格式与离线/CSP边界。未新增依赖或权限，PDF只运行原有回归。

## 改动

- 将文字索引与高亮处理收进独立 `reader-text.js`。当前文档首次需要时建立文本节点/UTF-16偏移索引，普通文本偏移直接查询，锚点范围用二分查找；不缓存整本书或跨文档共享节点。
- 文本或子节点变化会使索引失效；同一个JavaScript任务内，也会先读取尚未投递的MutationObserver记录。字体、颜色等属性变化不使文字索引失效。
- 高亮范围先统一解析、排序并合并交叠部分，再按文本节点批量生成片段；避免每条笔记扫描整章。旧笔记仍按首次引用文字匹配，原生存储中的每条笔记不合并。
- 笔记和文字都未变时保留原高亮节点与选区；无笔记时不为了高亮预先构建索引。实际内容变动后，即使再次传入相同配置，也会更新高亮，不能被配置去重提前跳过。
- 原生阅读页按文档加载两段应用脚本，后续字号/主题/尺寸更新仅传入配置。所有原有脚本回归使用同一加载入口，避免测试与应用漏载模块。

## 证据

同一API36 WebView环境，对照提交 `b0cd564` 原脚本和优化实现，包装实际的文字TreeWalker调用计数，未替换DOM行为。

| 样本 | 原实现 | 优化后 |
| --- | ---: | ---: |
| 3000段正文，25次锚点定位的整章文字扫描 | 25 | 0（已有索引） |
| 400段正文，132条含交叠高亮的文字扫描 | 133 | 2 |
| 相同笔记下切换字号/底色 | 重建高亮 | 高亮节点、选择起止和文字保持不变，扫描0次 |

一次受控样本的定位脚本批次耗时28.4→14.9ms，高亮同步配置计算21.5→1.5ms。耗时未设通过阈值，不能换算成真机帧率或续航。初次采样包含等待布局的总耗时79.4→92.5ms，并未缩短；之后才把同步计算与布局等待分开测量。主要可重复证据是遍历次数和真实行为断言，不宣称所有场景的总延迟都同比改善。

新增3项实际WebView测试：文字索引复用；同任务内插入/字符修改、相同配置重用、UTF-16 emoji与元素端点、笔记拆分/移除后的偏移；批量交叠高亮、旧引用、活动选区、章末和空文本。初轮旧实现2/3失败，优化后3/3通过。临时基线资源与实验分支已删除，APK与测试包也检查了没有遗留基线副本。

独立只读审查指出“相同配置在刷新文字前返回”和空笔记预先构建索引的问题。加入严格的同任务/同配置用例及冷启动扫描断言，先复现两项失败，再修复并通过。增加活动选区两端节点、偏移及文字的保留断言。审查未发现Critical；最终运行结果由执行者验证。
