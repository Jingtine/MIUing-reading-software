# 文字阅读跳转返回 · 0.6.3

目标沿用用户确认的“流畅、美观、接近原版、轻量”。本轮补齐 EPUB/TXT 的跳转返回，收拢主动跳转和位置保存逻辑。

## 行为与实现

- 目录、书签、笔记、搜索、书内链接及菜单章节/进度跳转统一保存来源。左下返回按钮逐次恢复章节、章内进度和 UTF-16 锚点；自然翻页、滚动、主题调整不写历史。
- 当前阅读会话最多保存 20 条来源，相邻相同来源去重。Activity 重建通过原始值恢复；关闭重开图书清空会话。
- 菜单滑块在菜单内保存预览值，确认后才跳转，返回时恢复拖动前的真实正文位置。
- 加载期间暂时禁用主动跳转；章节读取失败后仍可返回或另选章节，失败页不记为有效来源。相同失败章节再次调整进度或切换滚动模式也能恢复操作。
- 旧页面的进度回调由跳转序号过滤，避免覆盖新目标。返回弹出来源，不反向压入当前位置。
- 返回按钮使用底栏已有的 48dp 空间，正文视口保持原尺寸。各跳转入口复用同一函数，书签和笔记不再先后重复保存同一个目标。

新增实现文件只有一个小型位置值与 Compose saver。没有新增依赖、权限、后台任务或跨章 DOM 缓存；历史仅保留最多 20 组原始值。PDF 沿用既有阅读功能并纳入完整回归。

## 验证过程

新增四项实际界面用例，覆盖连续跳转/返回、Activity 重建、关闭重开、字号改变不写历史、滑块预览前位置、书内链接/搜索/笔记返回及章节文件缺失。原有书签恢复用例也增加了返回来源断言。

最初两项核心用例在旧版失败，均因缺少返回入口；实现后通过。独立只读审查指出旧进度覆盖目标和失败章节无法离开的问题；增加缺失章节用例先复现失败，再修复。后续复查又发现同一失败章节调整进度后可能再次锁住，扩展用例先复现，再修复；最终用例还覆盖失败页切换滚动模式。审查复核未发现新的实质问题。

核心 12/12、JVM 几何 1/1、开发 APK/测试包构建、两段 JS 语法检查通过。Android lint 为 0 errors、20 warnings。

## 视觉和性能边界

返回入口显隐不改变正文视口的行为由实际界面测试断言。截图见 [手机](previews/phone-reading-history.png)和[平板](previews/tablet-reading-history.png)。已目视检查两张截图：返回入口、页码及菜单显示正常，正文与底栏没有重叠，平板双栏正文完整可读；这只验证当前界面，不代表原版逐像素验收。

保留既有搜索按章节跳转的行为，精确命中跳转仍需后续完善。尚未测量实体设备上的帧时间、堆内存和电量；不据此宣称已完成流畅性或原版一致性的最终验收。
