# 跟手翻页：0.6.9

EPUB/TXT 卷页由触发后播放扩展为水平拖动预览，松手后完成或回弹。正文、章节及保存位置在预览期间保持不变。相邻章节预览首页或末页，确认翻页后才通过现有导航保存位置。点按、淡入淡出、连续滚动、选区、书内链接及系统关闭动画行为继续保留。

## 实现和边界

输入状态独立放在 `reader-gestures.js`，原排版引擎计算目标页。12 CSS px 后识别水平拖动；松手超过视口28%则完成，最近100ms内的快速滑动也可在8%之后完成。反向拉回会减小折页进度；第二根手指、选择、取消、重排或离开页面会取消预览。仍保留旧的只有起止事件的慢滑动兼容路径。

原生持久宿主只保留一个正文 WebView 和最多一个不接受输入、不参与无障碍、不保存进度的预览 WebView。两者复用同一个受限本地资源加载器、CSP、排版脚本和字体配置。预览按相邻章节和排版配置缓存一份；书籍、窗口或排版变化时释放。网络、书内脚本和应用权限未扩展。

源页、目标页各最多200万像素（ARGB快照合计约15.3MiB；不含 WebView 自身内存），每次拖动各捕获一次；移动时只更新折页比例。复用路径、矩形、矩阵和渐变，避免逐帧分配绘图对象。等待 Chromium 视觉状态回调后取图；相邻章节切换期间保留目标页，待新正文准备并完成绘制后释放。

预览准备最多等待3秒；失败或超时只在已确认松手时退化为直接翻页，取消不会推进正文。已经准备好的预览可以持续按住，不再受加载超时影响。跨章替换有5秒视觉清理上限，旧回调受 WebView 和手势编号保护。

纸背及折痕继续使用近似几何；这次完成了跟手交互，没有声称与 Apple Books 的曲面、触感逐帧一致。全书页码、逐项搜索结果及额外中文排版选项仍待后续工作。未测量实体设备的帧时间、耗电或内存峰值。

## 回归与审查

新增真实 Android 输入测试覆盖：未松手时的双页折页及位置不变、反向拉回、恰好一页提交、相邻章节取消与正反落点、ACTION_CANCEL、拖动中排版变化、Activity 重建、长时间按住、快速连续拖动及键盘打断。快照用例检查两张图都已准备好且各未超过像素上限。已有8项翻页测试保持有效。

旧版两项新增测试先在持有手指时等待预览失败；实现后通过。长按回归又复现了准备超时错误影响已加载预览的情况，现已取消该计时。独立审查发现两条键盘/无障碍输入竞态：旧触摸结束后多翻一次、跨章提交后旧点击继续导航；均先复现再修复。Node 直接执行实际手势模块的4项测试覆盖这两条顺序、多指取消和书籍边界；Android WebView 同样复现并验证了双翻页路径。

构建、Core12项、JVM几何1项及 JavaScript 语法检查通过。Lint为0错误、21警告（本轮新增1条颜色转换KTX建议；其余为已有条目）。

完整回归还暴露了测试工具的两处时序问题：新文档配置存在时，字体/分页恢复尚未结束；另一个线程反复构造 LibraryStore 读取 AtomicFile，会和主线程写入竞争，读盘恢复逻辑可能还原旧备份。诊断日志确认正文已正确发布末页和锚点，但测试读取后索引变回旧锚点。现已等首次定位回调及实际落点，并在主线程串行读取测试断言；临时生产日志已移除，未为此改动导航逻辑。最终个人包仍是下面核对的同一份冻结产物。
