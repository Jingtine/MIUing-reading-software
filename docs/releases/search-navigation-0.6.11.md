# 本章逐项搜索导航 0.6.11

版本18，compile/target36、min26。本轮继续完善 EPUB/TXT 的实际阅读流程。

## 行为

搜索列表仍按章节分组，点选进入第一处匹配；阅读页显示“本章 n / 总数”，可逐项上一处/下一处，边界按钮禁用。只标出当前匹配，已有笔记仍保留。输入查询不会移动正文，逐项查看不会追加返回历史；一次返回即可回到本次搜索前的原文。关闭搜索移除临时标记，保留当时正在看的位置；旋转和字体变化保留选中序号及原文。

导航控件叠在现有阅读工具区域，不改变正文视口。界面说明直接附在按钮上，使无障碍节点与实际禁用状态一致。

## 实现和边界

沿用真实 WebView 的正文索引，不使用 Android Html 发现阶段的偏移作为锚点。字面匹配仍支持跨行内元素、等价空白与 Unicode 大小写扩展；每次流式遍历只保留当前及最后一次匹配，计数不创建全部命中对象数组，也不为每处结果增加 DOM 标记。选中范围与已有笔记合成非嵌套片段，保留原始文本。

当前文档通过已有受控桥发布匹配序号/总数，旧文档销毁后回调失效。SearchNavigation 只呈现控件；来源历史和导航仍由 ReaderScreen 处理。ReadingLocationCapture 从当前 WebView 捕获实时位置，校验文档所有权后关闭搜索，避免使用滚动防抖尚未保存的旧位置。继续最多一个正文和一个辅助 WebView，没有引入新依赖、权限或后台全文索引。

本轮只完成本章逐项导航；全书逐项列表、跨章上一/下一匹配仍未实现。复杂 EPUB 的章节发现继续沿用 Android Html，隐藏内容可能与浏览器不同，实际命中及计数以正文为准。没有新增 PDF 功能，也未宣称原版视觉完全等价。

## 验证

最初5项新用例全部失败，随后3项实际渲染用例通过：重复文字跨元素、Unicode 大小写扩展、精确第二/第三处位置、重叠笔记和10005处匹配计数。界面用例覆盖逐项切换、边界禁用、旋转保留、关闭不移动及一次返回来源。

独立审查指出滚动后立即关闭会读到尚未保存的旧锚点。新增用例将正常180ms进度防抖延迟以确定性复现：当前原文锚点6109，关闭后却回到24。改为实时捕获后，新旧6项新增用例全部通过（38.763s），复查未发现新问题。

Core12项、JVM4项、Node手势输入4项和五份JavaScript语法检查通过；两种构建成功，Lint为0错误、22警告。最终冻结安装包矩阵（2026-11-22）：

平板首轮两条既有测试仍按单页状态解析，且假定全书55%必定有非零章内锚点；双栏时该位置实际可落在第二章首屏。测试改为解析物理页范围、选择75%并明确验证第二章，保留字号变化、首末页及精确书签锚点检查。应用APK没有因此改动，修正后的两项单独重跑均通过。

手机89项全通过后，又追加通过最新两项页码/书签用例（23.988s）；Android8个人版在46项全通过后，也追加通过这两项（23.572s）。实际界面已目视核对：[手机](../previews/phone-search-navigation-0.6.11.png)、[平板双栏](../previews/tablet-search-navigation-0.6.11.png)，第二处匹配标记和序号均可见。三个专用模拟器均确认测试书库为空、字体缩放和动画设置恢复、窗口覆盖重置后关闭。
