# 0.7.1：便携书库备份

在主页或书库右上角点击“⋯”（书库备份），选择“导出备份”或“恢复备份”，通过 Android 系统文件选择器保存/选择 ZIP。无需存储或联网权限。

## 包含哪些数据

- 七种已支持格式的图书原文件；MOBI/AZW/AZW3/FB2 同时保留已转换的 EPUB 阅读副本。
- 可用封面、阅读进度、正文锚点、已读/欲读状态、书签、文字高亮/笔记、PDF 笔迹和藏书。
- 不包含内置或私人字体、阅读外观设置、解压缓存、APK、账号或云同步。

恢复时仅补入书库中缺失的图书。同一原文件以 SHA-256 识别；已有图书的进度、书签和批注保持当前记录，藏书名称合并。完成后显示恢复/保留数量。旧设备原目录删除后，恢复的图书与阅读副本仍可使用。

## 复用的 GitHub 技术

使用 [Zip4j 2.11.6](https://github.com/srikanth-lingala/zip4j/releases/tag/v2.11.6)，对应上游提交 `c60f552986eb90e6862572b4209444c5435e423f`。复用 ZIP/Zip64 流式写入、条目读取与 CRC 校验；通过 Maven Central 固定依赖 `net.lingala.zip4j:zip4j:2.11.6`，Apache-2.0 原文随 APK 放在 `assets/licenses/zip4j-LICENSE.txt`。

SAF 接入沿用项目已有 AndroidX Activity Result API，参考 [Android 官方 storage-samples](https://github.com/android/storage-samples) 的系统文件访问方式。没有复制其他阅读器的整套 UI、账户或数据库层。

## 实现与保护

`BookJson` 共用原书库序列化结构，避免两套阅读记录格式漂移。`LibraryBackup` 只负责便携数据与分阶段校验，`LibraryStore` 一次性合并并原子发布索引，`BackupDocumentExport` 管理系统目标写入及异常清理，菜单只负责交互和操作生命周期。

ZIP 内为版本 1 的 `manifest.json` 和生成的 `books/<原文件SHA-256>/...` 路径；逐个记录文件大小及 SHA-256。拒绝未知/缺失/重复条目、异常路径、分卷、加密和未知版本。原文件哈希也必须与书籍身份一致。不会根据 ZIP 中任意路径直接解压。

在调用 Zip4j 前无分配检查其实际选择的 EOCD/ZIP64 目录及每个中央目录头，限制条目数、变长字段和总范围。避免仅验证一套字段、上游却解析另一套字段造成大内存分配。库完成 CRC 检查后再校验清单中的大小和 SHA-256。

恢复先完整暂存验证，再迁入缺失图书目录、提交索引；失败或取消清理暂存，提交失败回滚新迁入目录与内存记录。不会覆盖已有目录，发现孤儿目录时提示先修复。`AtomicFile.finishWrite` 的重命名失败可能只记日志，因此保存后核对实际落盘字节，防止仅在内存中显示成功。

导出先在缓存生成完整归档，再流式复制至用户选择的位置。写入/关闭失败或取消时清理缓存并尝试删除不完整目标；部分文件提供器可能拒绝删除，需要用户自行清理该目标。

## 限制

- 归档上限 8 GiB，展开文件合计 16 GiB，清单 16 MiB，中央目录 16 MiB，图书 10,000 本。
- 单原文件上限 1 GiB；转换格式原文件仍为 64 MiB；单阅读副本 256 MiB，封面 16 MiB。
- 请保持应用打开并预留本地暂存空间；操作可取消。旋转会取消正在进行的操作。进程被系统直接终止时无法保证执行清理；提交前若已迁入目录，可能留下孤儿目录，需要保留数据后修复。已有书籍及索引不会被恢复覆盖。
- 此版本没有自动云备份、阅读外观设置迁移或覆盖已有记录的恢复选项。换机前应确认备份文件已保存到可取回的位置。
