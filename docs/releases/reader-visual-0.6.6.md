# 阅读页视觉对照 · 0.6.6

本轮依据已有的固定 iOS18 官方阅读页图，校准真正可观察的阅读页差异，参考来源见 [阅读控件依据](../reference/reader-chrome-reference.md)。

## 改动

- 返回原文入口移到左上：反色圆形返回图标加来源章节，继续使用已有历史栈和锚点。右上关闭、顶部居中状态、底部位置和右下菜单保留。
- 菜单按钮从圆形三横线改为圆角方形、两横线加三点的自绘矢量图形。无需复制 Apple 图片、图标或字体。
- 状态文字采用次级层级，去掉多余字距；返回标签采用常规字重。按实际主题前景/背景计算最低不透明度，兼顾次级层级与普通文字至少4.5:1的对比度，不直接照抄截图的淡灰数值。
- 无自带字体的书籍使用系统衬线回退；仅设置 WebView 的标准字体，不覆盖书籍 CSS 指定的字体，也不修改主题偏好或书籍内容。
- 阅读主窗口、菜单、主题与底部面板的系统栏跟随相应背景明暗；旧 Android 同步设置背景颜色，离开阅读时还原原有书库设置。PDF 共享系统栏适配，控件组织、渲染和数据处理不变。

顶栏44dp、底栏48dp正文留白不变。返回入口显隐不重新分页；字体回退本身会改变原先无样式文字的排版，位置仍由文本锚点恢复。

## 证据

初轮返回测试停在起始位置，诊断发现手机 AVD 遗留了160dpi平板覆盖，实际阅读视口为1080 CSS像素。显式恢复1080×2400/420dpi后，基线明确在“返回入口必须在左上”断言失败；字体基线同一文本宽度为254.768 CSS像素，衬线对照为289.083。临时基线文件在 finally 中恢复，没有混入最终包。

首组实际 UI、字体和锚点用例5/5通过。一次独立审查指出浅色状态文字对比度不足；新增全主题对比度用例先复现3.64:1，再改为最低可读不透明度计算并通过。同时截图发现深色背景下系统栏图标仍为黑色，新增实际系统栏及退出还原用例先失败再修复。修复定向5/5通过；六个浅色与六个深色配色均接受数值检查。

最终冻结包验证结果（2026-11-20 运行，11-21 核对交付）：

| 环境 | 范围 | 结果 | 耗时 |
| --- | --- | --- | --- |
| Android 16 手机，1080×2400 / 420dpi | 完整仪器测试 | 53/53 | 437.290s |

| Android 16 平板窗口，1600×1200 / 160dpi | 相关平板回归 | 32/32 | 375.806s |

相关32项包含阅读控件17、字体1、锚点/笔记1、导入冒烟2、翻页8、主题面板2和 PDF 交互1。Android 8 另通过系统栏与配色定向2项。手机完整回归包含短横屏菜单用例；归档的旋转窗口截图来自平板窗口，不作为手机短横屏截图。

Core 12/12，JVM 几何1/1，调试应用与仪器测试包构建成功，JavaScript 语法检查通过；Lint 为0错误、20条已有警告。最终应用包27,214,501字节，SHA256：`15B0C9B2CA3F29ECFCEDE612CFF38A3295095767676B1E71EAD4CA3854AE306E`。验证后未改应用源码。

## 保留边界

来源暂显示章节，底部仍显示实际本章页数；尚未实现原图中的全书分页。该版本正文采用 Android 系统字体回退，未提供原版所列的实际正文字库，图标为近似；菜单、按钮等界面文字仍应跟随 Android 系统，不要求换成 Apple 字体。窄屏、大字号时状态文字允许省略，保持按钮独立空间；未完成人工 TalkBack 全流程和实体设备逐页视觉验收。展开菜单精确尺寸、分享、方向锁定及跟手卷页继续保留在对照清单中。
